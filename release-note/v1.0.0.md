# Ariadne Engine – Version 1.0.0 – Release Notes

**This is the first general-availability release of the Ariadne Engine.**
Version 1.0.0 builds directly on `v0.3.1` (and the pre-release `v0.4.0-rc1`) and delivers workspace file management, guided knowledge graph creation, alpha chats, the new embedded **Ladybug** graph core with automatic Kuzu migration, a standalone speech-recognition service, per-user automation policies, and a hardened monolith deployment, which increases performance and security.

### Key Features:

  1. **Workspaces & File Explorer**
     * New workspace explorer: browse, open, upload, and download the files of an AI workspace.
     * Workspace uploads are governed by a `workspace_upload` policy block (size limits, allowed extensions) with automatic cleanup of stale upload parts.
     * File access rights are now evaluated per sub-path instead of by parent directory.
     * `fs_read_command` is hardened against binary files.
  2. **Knowledge Graph Creation (LTM)**
     * Create long-term-memory knowledge graphs from workspace files, manually or assistant-guided.
     * Guided creation runs isolated subagent chats per workspace item, with live run details, run deletion, and recovery handling for interrupted runs.
     * Custom Graphiti extraction instructions per LTM dataspace.
     * Reworked graph search & query tools with an updated `explore-longterm-memory` skill and more flexible, larger tool limits.
  3. **Alpha Chats & Wizards**
     * New **alpha chat** chat type for lightweight, exploratory conversations, creatable from the dashboard and the add-chat flow.
     * Introduce different wizards for creating contexts and long-term memory dataspaces.
     * Fixed context-app launching.
     * Introducing dynamic context switching: you can now dynamically import abilities from other contexts into your current context.
  4. **Chat Management: Copy, Move, Split & Search**
     * Copy and move chats between contexts; split chats at any message into new chats.
     * New, improved chat-message search tool for the AI.
  5. **Manual Compaction & Context Size**
     * Manually create compaction checkpoints (app button) with streamed compaction runs.
     * New context-size evaluation endpoint and "ghost prompt rescue" for duplicated tool calls.
  6. **Ladybug Embedded Graph Core (replaces Kuzu)**
     * The embedded Graphiti database is now **Ladybug v0.19**.
     * **Automatic one-way migration**: existing Kuzu databases are migrated to Ladybug automatically before the server starts; a backup of the original data is kept (`AAA_LADYBUG_MIGRATION_BACKUP_ROOT`).
     * WAL-corruption recovery: corrupted Ladybug WAL files are detected and recovered via checkpoint snapshots.
     * `AAA_GRAPHITI_BACKEND` now accepts `ladybug` (default for native) or `falkordb` (default for Docker); the legacy value `kuzu` selects the embedded backend.
  7. **Standalone Whisper Service**
     * Speech recognition (faster-whisper) now runs as a separate background service with its own worker pool.
     * `AAA_FASTER_WHISPER_SERVICE_MODE`: `integrated` (managed by the engine, default) or `external` (bring your own service via `AAA_FASTER_WHISPER_BASE_URL`).
     * Model downloads are controlled and completed **before** server start; health checks respect pending model downloads when models are switched.
  8. **Per-User Local Automation Policies**
     * Each user can define their own filesystem roots (`AAA_STORAGE_BASE_DIR/<identity_key>/local_automation_policy.json`); terminal mode and sandbox settings always come from the global policy.
     * Optional user policy template (`local_automation_user_policy_template.json`) pre-seeds new users automatically.
     * Mutation flags: `AAA_ALLOW_USER_LOCAL_AUTOMATION_POLICY_MUTATIONS` and `AAA_ALLOW_USER_MCP_REGISTRY_MUTATIONS` (per-user MCP registrations).
  9. **Reworked Terminal & File Tools**
     * New `exec_terminal_command` with a terminal process supervisor: long-running/background processes stay alive across turns and can be read from, written to, and terminated via `terminal_process`.
     * `edit_file` reworked: precise line/anchor-based editing without explicit revisions.
     * The legacy terminal mode value `linux_sandbox` is automatically migrated to `bubblewrap`.
  10. **Model Routing & Reasoning Contracts**
      * Centralized model routing: cloud premium models are now defined as stable product definitions, and background tasks (dreaming, LTM cache sync) route through an explicit model hierarchy with fallback rules.
      * Generic reasoning contracts for model families without an explicit configuration.
  11. **Document Processing**
      * Images are now extracted from documents **including from tables**; redundant file-description calls were removed from the pipeline.
      * Indexed documents can export their additional markdown resources.
      * MCP tools can return images — handled as "image download into engine".
      * Default document processing can be overridden to avoid a potentially slow default model.

### Key Improvements (Performance & Stability):

  * **Worker Health Checks & Diagnostics** — the supervisor now monitors worker health with configurable timeout/grace/retry (`AAA_WORKER_HEALTHCHECK_TIMEOUT_SECONDS` = `60`, `AAA_WORKER_HEALTHCHECK_STARTUP_GRACE_SECONDS` = `30`, `AAA_WORKER_HEALTHCHECK_MAX_CONSECUTIVE_FAILURES` = `2`). Hung workers (e.g., during heavy embedded-database activity) are detected, sampled with tracebacks, and restarted instead of taking the engine down. Structured exit/diagnostic reports (`AAA_WORKER_DIAGNOSTICS_*`) support incident analysis.
  * **Single-Process Modular Monolith** — the engine is now a modular FastAPI monolith behind a single application factory. The internal service-hop environment variables are gone (`AAA_FLOW_INTERFACE_PORT`, `AAA_GENERAL_CONVERSATION_INTERFACE_PORT`, `AAA_LOCAL_GENERAL_STORAGE_PORT`, `AAA_MIDDLEWARE_PORT`, `AAA_LOCAL_AAA`, `AAA_DOCUMENT_EXTRACTOR`, `AAA_DOCUMENT_EXTRACTOR_PORT`, `AAA_FASTER_WHISPER_SERVICE`); one process now serves everything (the whisper service runs alongside it). Simpler deployments, fewer moving parts.
  * **Centralized token counting** — a robust, centralized token counter powers context-size evaluation, pruning, and compaction decisions (fixes undervaluing of message arrays).
  * **Subagent stability** — subagent execution was reworked to reduce write-operation conflicts on the graph database; join-subagent streams are annotated so the frontend can render them.
  * **Leader election & resilient sync** — LTM cache sync and dreaming now have leader selection with retry and clean shutdown handling, so interrupted syncs do not corrupt or stall the graph database.
  * **MCP hardening** — Claude-compatible MCP config schema support, robust tool loading with error logging, image response handling, and more robust tool-call dispatching.
  * **Model downloads before start** — LLM and whisper model downloads happen before server start and are respected by health checks.
  * **Uvicorn pinned to 0.37.0** and worker-spawn issues fixed in Docker for predictable runtime behavior.
  * **aarch64 (ARM64) Linux build support** for the embedded model/graph stack (Ladybug, CTranslate2).

### Upgrade Notes for Operators:

  * **Kuzu → Ladybug migration runs automatically** on the first start after upgrading from v0.3.x. The original Kuzu data is kept as a backup (see `AAA_LADYBUG_MIGRATION_BACKUP_ROOT`). The migration is one-way.
  * **Docker images**: use `ariadneindustries/ariadne-engine:1.0.0-on-prem` and `ariadneindustries/ariadne-webapp:1.0.0-web-bff` (tags referenced in `docker-compose-example.yml`).
  * **Removed environment variables** (internal service addressing — no replacement needed): `AAA_FLOW_INTERFACE_PORT`, `AAA_GENERAL_CONVERSATION_INTERFACE_PORT`, `AAA_LOCAL_GENERAL_STORAGE_PORT`, `AAA_MIDDLEWARE_PORT`, `AAA_LOCAL_AAA`, `AAA_DOCUMENT_EXTRACTOR`, `AAA_DOCUMENT_EXTRACTOR_PORT`, `AAA_FASTER_WHISPER_SERVICE`.
  * **New environment variables**: see the updated [README](../README.md) — in particular the `AAA_WORKER_HEALTHCHECK_*`, `AAA_FASTER_WHISPER_SERVICE_*`, and user-policy variables.
  * **Ladybug tuning (advanced)**: `AAA_LADYBUG_BUFFER_POOL_SIZE_BYTES`, `AAA_LADYBUG_MAX_THREADS_PER_QUERY`, `AAA_LADYBUG_QUERY_TIMEOUT_SECONDS`, `AAA_LADYBUG_EXECUTOR_QUEUE_SIZE`, and related variables.

### Ariadne Engine App → UI Updates:

  * **Workspace Explorer** — new screen to browse, open, upload, and download context files, incl. document links in chat.
  * **Alpha Chat** — create alpha chats from the dashboard and the add-chat flow; context switching and notification routing fixed.
  * **LTM Management & Graph Creation** — reworked LTM management view (graph gravity, node highlighting), dataspace details incl. custom Graphiti instructions, and the new guided graph-creation flow with run details and deletion.
  * **Chat Split / Copy / Move** — split button with bottom sheet; chat copy and move; chats are sorted by latest message activity.
  * **Compaction & Context Size** — manual compaction button with streaming; token estimator for the context size directly in the chat input.
  * **Model handling** — the last used model is stored per context and auto-selected; read-only dataspace hints corrected.
  * **Files & Media** — camera capture (taking pictures), attaching already-existing files to new messages, fixed file/image drop & attachment in the dashboard.
  * **Subagents** — improved visualization: streamed tool calls, join-subagent streaming, stable colors and loading states.
  * **Context Apps** — context-app subpage in chats, improved app launching, user reference backend calls.
  * **Quality of life** — centralized error snackbars (incl. browser fixes), fixed notification "already seen" bug, inline request cards replace blocking `ask_user`/context-switch dialogs, Linux microphone & camera setup hints, full translations for the new views.

### Docker & Deployment:

  * New image tags: `ariadneindustries/ariadne-engine:1.0.0-on-prem`, `ariadneindustries/ariadne-webapp:1.0.0-web-bff`.
  * Terminal sandboxing in Docker is unchanged (bubblewrap with `privileged: true` + `security_opt`), see the README.
  * Speech recognition can now run as a standalone external service if you prefer to manage it yourself.
  * Native binary: Windows and Linux (Ubuntu); CUDA/CPU model support; aarch64 (ARM64) Linux builds for the embedded stack.
