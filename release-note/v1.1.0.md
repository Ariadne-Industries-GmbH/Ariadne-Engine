# Ariadne Engine – Version 1.1.0 – Release Notes

Version 1.1.0 builds directly on `v1.0.0` and delivers the **file-based document pipeline** (fast and refined document artifacts replace the embedding/vector retrieval layer), **workspaces linked to contexts**, **browser automation** for the agent, a **sglang model provider with server-side token counting**, **cost-aware queue admission** in front of the LLM proxy, device pass-through for the bubblewrap sandbox, and a much stronger **workspace explorer** in the app.

**Work in progress: the Docker dev sandbox.** The runtime and permission layer behind it is implemented, but this release neither ships a published sandbox image nor a Docker sandbox that is operationally ready and fully tested. We plan to complete it with version 1.2.0. Native terminal automation with `bubblewrap` is unaffected and remains the supported path.

Alongside the features, this release fixes the failure families that surfaced in larger production installations: full-text message search on big storages, engine startup after skipping several versions, stale background processes, and tool calls with unknown arguments.

### **IMPORTANT**

* **Document grounding changed fundamentally.** The embedding/vector layer is gone, together with its agent tools and public threads. Document content is now read from the file system. Clients or skills that referenced the removed tools or threads must be updated — see **Upgrade Notes for Operators**, item 2.
* **The app 1.1.0 requires an engine 1.1.0 backend**, and vice versa: the app no longer offers any embedding/collection surface and reads the new document-artifact fields and workspace-explorer operations directly.
* **MCP bundle / skill package import is a preview, not a finished feature.** The backend path and the launcher entry point are live, but there are no tests, no secrets handling, and no app UI yet. Do not build a production workflow on it yet.
* **Browser Use needs a native interactive desktop session.** It stays disabled in containerized deployments (`AAA_ENGINE_CONTAINERIZED=1`).
* We still do not support every Windows path with the same depth as the Ubuntu bundle. Testing continues; Windows-specific bugs will be fixed.

### Key Features:

  1. **Document Artifacts on the Filesystem (replaces embedding RAG)**
     * Every uploaded document produces a **file-based artifact** (`document.md` plus optional `assets/`). Grounding runs entirely through the file system: the prompt names the absolute markdown path of the active variant and its asset directory, and the agent reads it with `fs_read_command`, `rg`, or `sed`.
     * **Two variants per source file.** `fast` (AnyDoc) is active immediately so uploads stay usable; `refined` (Docling) runs as a persistent background job and takes over only after validation. A failed refinement never deletes the active `fast` variant, and pending or stuck jobs are re-queued at engine start.
     * **Readable export names** instead of UUID paths, for example `document_exports/Jahresbericht_2026_xlsx/fast-<hash>/Jahresbericht_2026.md`. Umlauts and non-ASCII characters are preserved; duplicates are counted after `_` (no brackets, because these paths end up in shell commands).
     * Long-term-memory ingestion reads the **canonical** variant (the one that is active after all processing), with a bounded wait instead of an unbounded retry loop.
     * The fast path runs in its own worker, so a blocking upload no longer pays the Docling import cost (measured 0.92 s / 0 Docling modules instead of 3.09 s / 109).

  2. **Workspaces Linked to Contexts**
     * `create-context` and `update-context` accept `workspace_paths`: files and folders can be bound to a context permanently.
     * The completion context receives a `<workspace_context>` block listing the granted paths, and it is stated explicitly when a linked path no longer exists — instead of the agent making assumptions about its contents.
     * When paths are set, the `desktop-file-access` skill is loaded into the context automatically.
     * New backend thread `execute-workspace-explorer-operation` powers the new app features.

  3. **Browser Automation**
     * New low-level tools: `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_scroll`, `browser_back`, `browser_press`, `browser_screenshot`, `browser_close`, plus `browser_handoff` for handing a login over to the user (notification, 15-minute window).
     * Runs in a **visible browser profile per user** on the pinned `agent-browser` runtime. Setup source is configurable via `AAA_BROWSER_RUNTIME_SOURCE` (`npm` / `system` / `download` / `explicit`); the npm setup installs exactly `agent-browser@0.33.2`. Feature switch: `AAA_BROWSER_USE_ENABLED`. New engine skill: `browser-automation`.

  4. **Model Providers, Routing and Token Counting**
     * **New provider value `sglang`** in the existing `provider` field — no new configuration field and no proxy duplicate. Context-size evaluation now counts via `/v1/tokenize` instead of the vLLM-only render endpoint that sglang answered with HTTP 404, so sglang deployments get `quality: "exact"`, `source: "server"` instead of a local estimate in every turn. `reasoning_effort` is deliberately not sent to sglang, because the server rejects `high` and `max`.
     * **Premium is one model with three reasoning stages**: an upstream `glm-5.3-flash`, published as `Premium Low` / `Premium High` / `Premium Max`. No capability matrix, no fallback candidate, no output limit on the wire.
     * **Tokenizer-based token counting for premium models**: every premium request renders the prompt with the model's own chat template and counts real tokens (`token_count_source: "transformers"` instead of `"heuristic"`). Tokenizer artifacts are vendored with a pinned revision and checksums; refresh via `scripts/fetch_premium_tokenizer_assets.py` (`--check` verifies the checked-in state).
     * **Declared reasoning and message protocols** per model/provider combination (`replay_history`, `history_field`, `forward_reasoning_effort`, `enable_thinking`, `preserve_thinking`, `clear_thinking` — `null` always means "leave it out"). `proxy_family` is now optional, and a declared reasoning contract excludes it; both are validated at load time with no silent default. See `docs/reasoning_model_config.md`.
     * `xhigh` is supported as a reasoning effort. Image modalities are declared per premium stage in the routing declaration (`input_modalities` / `output_modalities`) instead of being hard-coded to text, so premium models can actually see images.
     * **Experimental support for Ternary Bonsai 2 27B** (PTQ1/PQ2) with four deployment presets calibrated by recomputed VRAM need: `bonsai2_ptq1_cuda_120k_x1` (<12 GB), `bonsai2_ptq1_cuda_101k_x2` (<16 GB), `bonsai2_ptq1_cuda_138k_x3` and `bonsai2_pq2_cuda_115k_x3` (16–24 GB), each with a stated reserve and mmproj GPU offload. Deliberately no preset above 24 GB or below 8 GB.
     * **Managed llama.cpp CUDA runtime for Linux** (runtime IDs `mainline-b10982`, `prism-b10685`, Ubuntu CUDA 12.8 archives, minimum CUDA driver 570.26).
     * Every EUrouter request carries the fixed governance values `data_collection: "deny"`, `data_residency: "EU"`, `max_retention_days: 0`, `eu_owned: true`; a caller cannot weaken them.
     * **New optional per-model field `provider_extras`** in `model_config.json`: a mapping with **no engine schema** for control fields that belong to a concrete provider endpoint rather than to the engine. The engine only carries the declaration to the selected proxy (as the internal `_provider_extras` marker, stripped centrally before the provider is called), validates that it is a mapping, and hands out a deep copy so a proxy can never rewrite the stored configuration of later requests. A model without the field is byte-identical to the previous behaviour, and a provider without support sees no change. EUrouter is the first consumer: its `provider` block can exclude upstreams (`provider.ignore`, merged as an order-preserving union, while the governance values above always win). Applies to both configuration paths — exclusive models in `model_config.json` and declared premium models. EUrouter also logs the upstream slug with the engine `request_id` per attempt (see the `upstream_provider=` log field, `unknown` when absent) so a repeated failure on one provider instance is readable from the log alone. Operator reference: `docs/provider-extras-model-config.md`.

  5. **Cost-Aware Queue Admission in Front of the LLM Proxy**
     * Each request starts as PREFILLING and becomes DESCODING at its first generated token. A request is admitted only if slots **and** compute budget are free: `D + P + 1 <= max_parallel` and `D*decode_compute_cost + (P+1)*prefill_compute_cost <= max_compute_cost_capacity`. Background: one prefill alongside three decoders pushed every stream down to 2–10 tokens/s on a Spark/GB10.
     * Optional `load_envelope` block in a `__queues__` entry of `model_config.json` with exactly `max_compute_cost_capacity`, `decode_compute_cost`, `prefill_compute_cost`. Strict validation, start abort on invalid values, **no default and no clamping** — without the block the behaviour is byte-identical to before.
     * Queue logging is now diagnostic: waiting messages name the blocking criterion and the current occupancy, finished requests report `total` / `queued` / `held`, and the timeout message names the lever `AAA_MW_QUEUE_WAIT_TIMEOUT_SECONDS`.

  6. **Docker Dev Sandbox (work in progress — planned for 1.2.0)**
     * The runtime and permission layer behind the Docker dev sandbox is implemented in this release's code: a configurable runtime and numeric container identity, automatic permission grants for writable roots that fail with named errors instead of silent fallbacks, platform checks per host CPU, and exact mount parity with the bubblewrap sandbox.
     * It is **not part of this delivery**: no sandbox image is published with 1.1.0, and the module is not yet tested to a state we would recommend for operation. Completion is planned for version 1.2.0 — operators do not need to deal with this module until then.

  7. **Configurable Device Pass-Through for Bubblewrap**
     * The sandbox mounts an empty `/dev`, so host devices were invisible to agent commands. The new `linux_sandbox.device_bindings` key grants single device paths explicitly (emitted as `bwrap --dev-bind-try`). Only absolute paths below `/dev` are accepted — never `/dev` itself, no relative paths, no wildcards. This is a **server-side key**: users cannot add or remove devices, and without the key the generated arguments are byte-identical to before. Docker mode ignores the key.
     * Operator documentation with per-hardware templates (NVIDIA/CUDA, AMD/Intel DRM, ALSA, USB, Fuse, V4L2, RDMA): `docs/linux_sandbox_device_bindings.md`.

  8. **Background Processes and File Tools**
     * `terminal_process` gained `action="list"` (`process_id` is now optional), returning status, exit code, command, timestamps and output sizes without the output buffers. Unknown process IDs return a typed error and the process row is closed as `not_tracked`, which counts as terminal — so `only_running` no longer lists forgotten processes as active.
     * Background processes carry a `status` field (`running` / `completed` / `failed` / `cancelled`) for filtering and correct state handling.
     * `fs_read_command` supports combined and single `-l` / `-n` flags for `rg` and `grep`, matching Linux behaviour.
     * Prompting for images attached through `fs_read_command` was improved.

  9. **Skills: Distribution and New Content**
     * Engine-owned skill directories are now automatic read-only default roots for every user ("Engine skills"), and `SkillManager` finally respects `AAA_GLOBAL_SKILL_DIRS` — skills listed there were previously invisible to the agent.
     * Correction that matters for operators: the separator of `AAA_GLOBAL_SKILL_DIRS` is the platform path separator (`:` on Linux). The documented "comma-separated" was wrong.
     * New engine skills: `browser-automation` and `icm-architect` (workspace/context mapping methodology). The `developer-autonomous` skill was brought in line with the current anchor-based `edit_file` API.

  10. **Uploads Decided by Content, Not by Extension**
     * Public upload threads accept Unicode plain text regardless of the file extension (source code, config files, unknown extensions), decided on the composed content MIME type. Pure text extensions with binary content are still rejected, and the ClamAV scan before publication is unchanged.
     * HTML and SVG are served as `text/plain` so they are not implicitly rendered in a browser.

  11. **Onboarding Preference for the Initial Assistant**
     * New global user preference `onboarding.initial_assistant.visibility` with `show_on_login` and `hidden`, served through the existing `update-user-preferences` / `get-user-preferences` threads — no new thread names, no new DTO shapes.

  12. **MCP Bundle / Skill Package Import (preview, not production-ready)**
     * New public threads (`get-package-import-capabilities`, `upload-user-package-chunk`, `prepare-user-package-import`, `install-user-package`, `discard-user-package-import`), a launcher entry point "Import MCP bundle", and an admin import path. Purely additive: no boot hook, nothing runs unless you trigger it.
     * Honest status: no tests, no secrets handling, the TTL cleanup hook is implemented but never called, and the whole app/UI side is missing.
     * The groundwork behind it is finished and takes effect immediately: MCP stdio arguments are stored losslessly (`command_json` and `cwd` on `MCPServerSpec` plus a data migration). Previously arguments were joined and split, which lost argument boundaries and spaces.

### Key Improvements (Performance & Stability):

  * **Full-text message search no longer hits the buffer-pool limit.** `search_message_chains` with a `pattern` now runs in two stages: a lean candidate query (keys and positions only) followed by hydration in bounded batches (`MESSAGE_SEARCH_HYDRATION_BATCH_SIZE` = 2000). Results, relevance scores, `total_matches` and pagination are identical to the previous broad query — validated against a production copy with 53,721 messages. A second stage removed a projection-only optional match that forced a hash-join build state, and the chain metadata loader now filters per batch (measured 3 instead of 5,427 rows per batch).
  * **Compaction is always a real model call.** The deterministic rule-based fallback summary is gone: a failed, timed-out, empty or rejected compaction aborts the run instead of continuing with an invented summary. The only summary without a model call is the structural last-resort collapse for a window no compaction call could fit, and it is labelled as locally extracted. An empty summary is rejected instead of being replaced silently.
  * **Agent round ceiling raised from 100 to 200**, and a compaction that really shrank the history resets the round counter (bounded to 5 refills). Runs that declare their own budget keep it unchanged. Long tool chains are no longer cut off right after their context window was freed.
  * **Tool-call dispatch validates arguments against the function signature.** An unknown argument field used to produce a 0 ms `TypeError` with nothing the model could act on; now it is a validation error naming the unknown fields **and** the valid parameters, and the tool function is not executed.
  * **`edit_file` no longer eats blank lines.** Range edits consumed the line break of the last replaced line and silently deleted the blank line in front of the next statement. Replacements are now terminated with the detected line ending; an empty replacement deletes exactly the anchored lines. CRLF files and files without a trailing newline behave as before.
  * **Token counting no longer falls through silently to the byte heuristic.** An `AttributeError` in a counting path aborts with `PromptTokenCountError` instead of being swallowed into an estimate, and that error class deliberately inherits from neither `RuntimeError`, `TypeError`, nor `ValueError` so no handler can turn it into a heuristic. Externally billed models may degrade in a fixed order, and only a missing artifact (`OSError`) triggers the last step.
  * **Exact premium token counting was actually reachable for the first time**: vendored artifacts were never read locally, the template path iterated tool-call arguments as a mapping while the wire carries a JSON string, and a processor setting produced a bare preprocessor without `apply_chat_template`. On an identical prompt the byte heuristic reported 542–557 tokens while the models reported 274–545.
  * **Extraction errors are no longer hidden**: a broken table output fails the refinement (status `failed`) instead of claiming the content is in `document.md`. Legacy re-exports that dragged the Docling import into every import path were removed, a stale import name that blocked `import generic_agent_interface.facade` was fixed, and two orphaned helpers that could only raise `NameError` were deleted.
  * **LLM wire correctness**: `chat_template_kwargs` stays inside `extra_body` only for the vLLM proxy; reasoning effort for flash-next templates corrected; reasoning shutdown now clamps to the declared `minimum_reasoning_effort` instead of sending a value the endpoint rejects; Mistral conversion merges consecutive user messages **after** role normalization so converted roles can no longer leave unmerged duplicates.
  * **Engine startup no longer blocked by foreign databases.** The user database migration resolves `<identity_key>/data.db` explicitly instead of recursively scanning every `*.db` file below the storage directory — browser profiles and agent-owned databases no longer block startup.
  * **Launcher usability**: the option list grows dynamically; with 14 presets plus a back entry, every option from the thirteenth onward had silently disappeared. Preset identity is only passed within one launcher run, so removed presets no longer hang on a saved setup.
  * **Integrated IDP allow list is now documented** (`docs/integrated_idp_account_allowlist.md`, `integrated_idp_accounts.example.json`), including `AAA_INTEGRATED_IDP_ALLOW_REGISTRATION` and `AAA_INTEGRATED_IDP_ACCOUNTS_FILE`. To be precise: the implementation and both variables were already present in 1.0.0; 1.1.0 is the first version whose README and docs describe them.

### Upgrade Notes for Operators:

  1. **Switch sglang instances to the new provider value.** Set `provider: "sglang"` in the model configuration instead of `"vllm"`; otherwise context-size evaluation stays on the 404-plus-local-estimate path. Known, deliberately accepted limitation: `/v1/tokenize` does not count image tokens, so vision prompts are underestimated on sglang (measured 59 counted vs. 122 actual image tokens).
  2. **Removed agent tools and public threads (embedding/vector path).** The tools `search_for_document_content`, `browse_document_content`, and `get_document_content_sample` no longer exist, and `create_ltm_refined_document_artifact` was removed. Removed public threads: `add-vector-embedding`, `delete-vector-embedding`, `get-all-vector-collections`, `query-file-embedding`, `query-vector-embedding`, `query-vector-full-text`, `query-vector-metadata`, `add-embedding-collection-to-context`, `remove-embedding-collection-from-context`. `stream_embed_files` and `stream_embed_files_into_context` keep their names but now export artifacts instead of producing embeddings. `linked_embedding_collections` left the context DTO, and `update_context` no longer takes the add/remove collection parameters.
  3. **Automatic data migrations run on first start** (one-time, no manual action, but they cost startup time):
     * `migration_20260911_1200` replaces document chunks and free embedding-collection graph data with the new artifact layout (`DocumentArtifact`, `DocumentElement`), migrates existing exports **without re-running Docling extraction**, and carries over existing provenance. Missing legacy exports are kept for a later idempotent retry and the artifact is marked `failed`.
     * `migration_20260916_1400` adds `workspace_paths` to `Context`.The chain-oriented search path without any filter set fails on an empty `WHERE` — measured identical before and after the search changes, deliberately not touched here.
     * `migration_20260909_1200` adds `command_json` and `cwd` to `MCPServerSpec`. Legacy `command` values are carried over with a split, which is lossy for arguments containing spaces — this affects the content of existing MCP server configurations, not the ability to run.
     * The three legacy document Chroma collections `files`, `external_files`, and `ai_notes` are deleted permanently at startup. Note that this deletion only works with the fix in this release; before, it failed silently.
  4. **Version jumps are fixed — important for customer updates.** Updating from a pre-August state used to crash at startup: a data migration called a current model function whose `RETURN` projected columns that are only created later in the same migration chain, producing `RuntimeError: Binder exception: Cannot find property …`. Because the migration entry was never written, **every** subsequent start crashed identically. Fixed with a minimal existence query and a correctly ordered column addition, covered by a new regression test that replays the whole pending chain (0809 → 0916) against a database with the old baseline schema. The migration is resumable: already migrated `.lbug` files finish the chain with a newly built binary, and Kuzu copies do not need to be touched again.
  5. **Breaking changes in DTOs and contracts.** The provenance response returns `FileWithDocumentArtifactDTO` with `DocumentArtifactDTO` / `DocumentElementDTO` instead of a chunk structure; there is a new `DocumentArtifactVariantDTO` (`artifact` + `active`); `replace_document_artifact` was replaced by adding/activating a variant; `DocumentArtifact.export_path` now ends with the markdown file (older paths ending at the variant folder are still resolved, nothing is rewritten in existing databases); the system-prompt template version moved 0.7.2 → 0.8.0. Credit and usage vocabulary: `mode` is now `low` / `high` / `max` (plus `standard` for unbilled sums) instead of `daily` / `work` / `deep` / `max`, and plan gates map to `premium_low`, `premium_high`, `premium_max`.
  6. **Export directories created under the old naming rule are not migrated.** Older `document_exports/<name>__<uuid>` folders stay where they are, and a delete operation finds both readable and key-suffixed folders — a document deleted after the update does not lose its legacy exports. New exports appear in the readable layout.
  7. **New configuration keys (all optional; without declaration the old behaviour is byte-identical)**:
     * `model_config.json`: the `load_envelope` block in a `__queues__` entry, `xhigh` as a reasoning effort, the `reasoning` / `message_protocol` block, and `provider: "sglang"`. Rule: set `proxy_family` only when no reasoning contract or message protocol is declared. `model_config_template.json` demonstrates both semantics.
     * `local-automation-policy`: `linux_sandbox.device_bindings` (server-side, absolute paths below `/dev`). The `docker_dev_sandbox` keys that `get-local-automation-policy` already reports (`runtime`, `container_user`) belong to the work-in-progress module below — please do not configure them yet.
     * Relevant existing switches: `AAA_MW_QUEUE_WAIT_TIMEOUT_SECONDS`, `AAA_BROWSER_USE_ENABLED`, `AAA_BROWSER_RUNTIME_SOURCE`, `AAA_ENGINE_CONTAINERIZED`, `AAA_ALLOW_USER_MCP_REGISTRY_MUTATIONS` (server-side opt-in for MCP bundle import), `DOCUMENT_FINALIZATION_WAIT_TIMEOUT_SEC` (1800 s).
  8. **Docker dev sandbox: no operator action is needed or possible in 1.1.0.** The module is work in progress and is completed together with a published sandbox image in version 1.2.0. Regular Docker deployment of the engine is unchanged and unaffected by this; terminal automation keeps running on `bubblewrap` (native) as before. The `docker_dev_sandbox` policy keys appear in responses already but have no operational effect yet.
  9. **Docker deployment without a browser**: set `AAA_BROWSER_USE_ENABLED=0` (already added to the example compose file). Browser Use V1 requires a native interactive desktop session.
  10. **Several fixes require a rebuilt binary.** The search fix, the Chroma deletion fix, the version-jump migration fix, and the sglang provider only take effect in a newly built binary. A correct branch or source state alone is not proof that a running instance has them.
  11. **Known limitations.** Refinement can make spreadsheets and Word tables more fragmented than the fast variant (lost headings, shifted table cells) while delivering embedded images losslessly that the fast path does not export for XLSX — check per file type which variant you read. The prompt hint does not always switch to the refined variant on its own. For `moonshotai/Kimi-K3` the chat template ignores `enable_thinking`. The chain-oriented search path without any filter set fails on an empty `WHERE` — measured identical before and after the search changes, deliberately not touched here.
  12. **Context creation with workspace paths works without a global policy.** `create-context` / `update-context` with non-empty `workspace_paths` used to be rejected with `400 "Local automation tools are disabled…"` even when the per-user policy or the default roots granted access. Invalid paths now report a typed storage validation error instead of a raw value error (still HTTP 400).

### Ariadne Engine App → UI Updates:

  * **Workspace Explorer** — replaces the old "AI files" area entirely (the old page only shows a relocation hint). Full file operation from the UI: select, rename, move, copy, delete, upload by drop, preview, and download, with actions derived from the location type and its access level. "Chat with files" starts a new chat directly from a selection plus a task prompt. The sidebar separates **folders** from **chat documents**, and engine-managed content carries a "managed by the engine" chip. New: create folder.
  * **Chat documents** — "Refine document" runs as an overlay with progress, thinking output, cancel, and minimize (minimized runs stay reachable through a floating pill; failures reopen the overlay). Status chips per document: not refined / refining / refined / ready, plus "refinement failed" alongside "ready" because the fast markdown version remains usable. Deletion names up to five linking contexts, warns what is permanently removed, and reports partial results. Deleted documents now appear in old messages as a "document deleted" tile instead of vanishing silently.
  * **Workspace links for contexts** — a new "Workspace" section in create/edit context and in the knowledge-graph assistant for granting the files and folders the AI should work with in that context.
  * **User preferences: saved decisions** — a new settings section shows what the app remembers (with timestamps, change, and "forget selection"), covering guided-vs-manual for context creation and knowledge-graph creation.
  * **Background processes** — new filter and sort area (process type, status, source thread/context with debounce, time window, sort direction, reset). The event history is no longer loaded automatically but on demand, with bounded pages and "show older", so opening a long-running process with thousands of events no longer freezes the page.
  * **Compaction bubble for automatic compaction** — automatic forward compaction is now shown as its own checkpoint bubble ("compaction checkpoint (automatic)") instead of only manual runs.
  * **Cross-app reconnect for chat completions without WebSocket** — completions use the buffered SSE reconnect path other features already use. A running completion is recognized whether another app instance of the same user started it or this app was reloaded; terminal cases are cleaned up and errors surface as a snackbar plus a repeatable error message instead of a dead placeholder.
  * **Direct navigation to the resulting chat** — split, move, and copy now return the target chat key and open it, switching the active context along.
  * **Dialog sizing and scrolling in the explorer** — dialog width follows the window (80 % of window width, min 480 px, max 1,200 px), long folder paths stay on one line with an ellipsis plus a full tooltip, the target-folder menu gets its own scroll area, and in "Start chat" only the selection list scrolls so the input field stays reachable.
  * **Markdown rendering in message bubbles** — inline code gets an accent color, a dark background, and a real monospace stack without any runtime font download (the generic fallback landed on Courier New on Windows and spread digits apart).
  * **Removed with the backend change**: all embedding search and indexing screens, controllers, routes, and the context link endpoints. Artifact status is shown as an element count instead of an embedding collection.
  * **Quality of life** — fixed the context dropdown showing the wrong context after a context switch; fixed a crash when starting a chat from the workspace explorer; fixed disposed controller errors in dialogs; corrected the misleading tooltip in the knowledge-graph assistant ("both paths are valid"); document lists in an open explorer refresh every ten seconds and stop polling when you leave.
